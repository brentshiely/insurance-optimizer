# Decisions and spec deviations

Append-only log. Each entry: what was ambiguous or changed, what was decided, why. Review these first.

- **D1 - Q1 option list is wider than the spec's Q1 sentence.** The spec's Q1 lists Auto, Home, Renters, Umbrella, Health and five Other items, but later sections need Motorcycle, Boat, and Towing/roadside to be selectable "in Q1". The derived `policies` set therefore includes motorcycle, boat and towing (see ARCHITECTURE adapter table).
- **D2 - Added a "which credit cards do you carry" question.** The spec says to cross-reference the card table and name the card, and to flag stronger when a held card carries the benefit; that needs to know the cards. Asked once, only when a card-linked Other item is held, as a closed list of cards in the table plus "other / none".
- **D3 - Card tranche is "roughly a dozen".** The spec names 8 starting cards ("Chase Freedom" and "Amex Blue Cash" being product families). The table expands families to their current products and adds benefit-rich popular cards to reach about 12. Final list in `research/cards-*.mjs`.
- **D4 - Analytics provider is pluggable and defaults to `none`.** The spec picks Plausible, Fathom or Zaraz without choosing one; no account exists yet. The adapter supports all three; the owner sets one in config.
- **D5 - Environment: no Node.** Unit tests run under macOS `jsc` via `scripts/test.sh`; the pure core is runtime-agnostic. UI behavior is verified in the Browser pane against recorded goldens.
- **D6 - Repository and base (revised 2026-10-10).** The owner chose to build on the existing Coverage Check app in `brentshiely/insurance-optimizer` ("this is a better version"), extending it rather than starting a new app. Work is committed to `main` of that repo, one commit per story. A scratch repo `brentshiely/insurance-overlap-explainer` was briefly created holding only the superseded first bootstrap; it is unused and can be deleted by the owner.
- **D7 - Hosting/analytics accounts are not touched.** Pushing to `main` does not deploy. `npm run deploy` (live site coverage-check.pages.dev) and analytics account setup are owner actions.
- **D8 - Gate questions on within-policy exclusions.** For sewer backup and flood, the wizard first asks (yes / no / not sure) whether the coverage is already on the policy and only raises the Question item for "no" or "not sure", so informed users are not nagged. The spec's "each surfaced as a Question item" is preserved for everyone who is or may be exposed.
- **D9 - The spec's "does not ask for the user's state" vs the host app's state picker.** The host app asks for a state and has state-driven findings; those stay. The new overlap engine is state-neutral: it never receives or branches on state and never names one, as the spec requires of its flags.
- **D10 - The engine ignores policy-screen numbers.** The host's per-policy fields are editable sample defaults (the page says "Editable sample data") and cannot be distinguished from user input. The engine therefore asks its own closed-list questions, with "Not sure", for every figure it needs (e.g. liability limits in the umbrella branch) rather than trusting those fields. This can duplicate a question for users who also edited the policy screen; accepted for honesty.
- **D11 - Jet ski / RV / ATV / E-bike are not in the overlap v1 scope.** The spec defers RV, ATV and jet ski as fast-follow and lists only motorcycle and boat. The host's existing powersports findings still handle all of them.
- **D12 - Modules, not a single file.** The inline script and styles move to `public/js/app.js` (ES module) and `public/css/app.css` so the logic is testable and CSP-friendly. The page therefore needs to be served over http(s) (it already is on Cloudflare Pages and via `npm run preview`); opening `public/index.html` straight from disk no longer works because browsers block module scripts on `file://`.
- **D13 - The existing app's commercial sources are left alone.** `app.js` cites some commercial/secondary sources (e.g. ValuePenguin, Progressive, Policygenius, AgentSync). The overlap spec's neutrality rule applies to the new flags; existing citations are listed in `docs/OPEN-ITEMS.md` for the owner rather than changed.
- **S2-1 - Condition DSL is strict.** `evaluateCondition` rejects empty `all`/`any`, extra keys, mixed forms, and an `answer` without exactly one of `is`/`in`/`includes`, and checks the whole tree before evaluating. Why: an authoring slip (e.g. `all: []`, which would be vacuously true) should fail loudly in tests, not silently show or hide a question. `env` is `{ answers }`, not a bare answers object, so passing the wrong thing throws instead of giving a wrong boolean.
- **S2-2 - Visibility edge cases.** (a) A `showIf` that references a question that is itself hidden hides the question, including inside `not` (the ARCHITECTURE rule, applied literally). (b) A reference to a question that does not exist hides the question at runtime (the wizard must not crash on an authoring bug) and is a hard error in `validateCatalog`. (c) A condition cycle throws at runtime and is a hard error in `validateCatalog`.
- **S2-3 - Answer normalization.** `prune` (and every read in the session) first sanitizes answers: unknown option ids, wrong shapes and non-question keys are dropped; multi answers are put in option order and deduplicated; an exclusive option wins over the others; an empty multi answer is "unanswered". Reason: a stale or hand-edited answer must not gate other questions, and equivalent inputs must produce byte-identical results. `policies` is the one reserved non-question key; it is sorted and deduplicated. `setAnswer`/`toggleOption`/`clearAnswer` validate ids (throw on unknown) but do not prune other answers, so flipping a gate back and forth keeps what the user entered; `evaluate` prunes.
- **S2-4 - `not_sure` on multi questions is exclusive.** The appended option is `{ id:'not_sure', label:'Not sure', exclusive:true }` for multi questions (plain `{ id, label }` for single). "Not sure" cannot sensibly be combined with a real selection. `exclusive` on option data (e.g. "None of these") has the same meaning.
- **S2-5 - Flag contract refinements.** `applies` may return `true` as shorthand for `{}`; `undefined` (a forgotten `return`) throws rather than silently never firing. `priority` is optional with default 100 (validated as a finite number when present) so a missing priority cannot break ordering or block a parallel story. `title` is templated exactly like `background`/`ask`/`reason`. Text returned by a function also goes through `{{token}}` resolution so a leftover token is always an error. Evaluation errors name the flag and field.
- **S2-6 - Context details.** `ctx.option(qid)` returns an array of option objects for multi questions (a single object for single). `ctx.answer('policies')` is `undefined`; use `ctx.holds`. The ctx, its answers and options are frozen so flag code cannot corrupt the catalog. `ctx.cardsWith(key)` counts only `primary`, `secondary` and `yes`; `unverified` and `none` never count (SPEC: unverified is never stated as fact). `ctx.cards()` reads the multi question with id `cards`; each option names its card via `value.cardId`, falling back to the option id with `_` changed to `-` (question/option ids are snake_case, card ids kebab-case). Validation checks that every `value.cardId` exists.
- **S2-7 - Validation scope beyond the story list.** Also checks: condition form vs question type (`includes` only on multi, `is`/`in` only on single), policy ids in `holds` against the adapter's list, `domain` from the closed list (flags and questions), `section` is snake_case, `id === key` for sources and cards, all six card benefit keys present (use `unverified` when unconfirmed), non-empty text fields, malformed `{{ }}` templates in static strings, and impossible dates (e.g. 2026-02-30). `cards` is optional in the catalog; `sources` is required. An https URL must have a dotted host (so `https://localhost` fails).
- **S2-8 - Two internal engine modules.** `engine/constants.mjs` (closed lists, reserved ids) and `engine/util.mjs` (clone/freeze/compare helpers) are shared by the engine files; they are pure and covered by the same source-scan test. The story lists six engine files plus the stub; these are additions, not changes to any contract.
- **S2-9 - Data module export shapes are part of the contract.** `data/catalog.mjs` imports named `QUESTIONS`, `SOURCES`, `CARDS` and the default array of each flag file; stories S3b, S4b, S5 and the flag stories keep those shapes. Documented in ARCHITECTURE "Parallel build rules".
- **S2-10 - Test infrastructure added.** `tests/fixtures/catalog.mjs` (small fake catalog; its `example.org` URLs are reserved documentation domains, never shown to users), `tests/helpers/purity.mjs` (deep freeze, copy, property-read recorder), and `tests/engine/purity.test.mjs`, which scans the module graph reachable from the engine and the catalog for forbidden globals and imports (skipped where jsc's `read()` is unavailable). Tests were mutation-checked against a scratch copy: breaking pruning, transitivity, the id tie-break, template checking, cycle detection, https checking, `not_sure` appending, the adapter's read set, or input purity each makes the suite fail.
- **S1-1 - What the golden master captures.** For every step: the text of `#stage` plus `#known`, taken from the DOM (not `innerText`, so CSS such as `text-transform` and viewport size cannot change it), one line per block element, whitespace collapsed. Controls are written into the text so their state is part of it: `[Own]` / `[*Own]` (selected, from the `sel` class) / `[Continue (disabled)]`, `{select: current | options: ...}`, `{input number: 5000}`, links as `label <href>` (so citation URLs are guarded). The only normalization is the summary's "N taps, S seconds". Deliberately not captured: the progress-bar width and the telemetry panel (bar width would change in every step when S13 adds screens, which would break the rule that S13's golden diff is only the new screens; telemetry is timing data), and anything visual (CSS, colors, layout, focus). Because CSS is not covered, step B must prove the CSS and JS moved verbatim by diffing them against the original inline text rather than relying on the goldens.
- **S1-2 - Replay mechanics.** Each scenario runs in its own hidden iframe, up to 6 at once, so a full run takes about 15-20 seconds. After every step the harness waits 250 ms, then until the page has stopped mutating for 100 ms, and for the two click types that navigate after the app's 140 ms timer (`button[data-q]`, "None of these") it also waits until the screen text has really changed, so a slow or throttled tab cannot produce a half-finished capture. A scenario stops at its first mismatch; the report names the first failing scenario in file order. The harness fails a scenario if the app throws or calls `console.error`/`console.warn` after it has loaded. Before each run it re-fetches the app and everything it references with `cache: "reload"`: `python3 -m http.server` sends no cache headers, so a browser could otherwise keep serving the old `index.html` after step B replaces it and the replay would silently test the old code.
- **S1-3 - Recording uses a small helper instead of hand-copying.** The golden files total about 300 KB of text. Copying that through a chat transcript by hand would be slow and error-prone, so `golden.html?record=1&post=1` POSTs each file to `tests/browser/record-server.py`, a stdlib-only dev helper (127.0.0.1, same-origin posts only, writes only `tests/browser/golden/<id>.mjs`, sends `Cache-Control: no-store`). The plain `<pre id="record">` JSON output also exists for anyone who prefers to write the files by hand; the file format is fixed by `goldenFileText()` and enforced byte for byte by `tests/browser/golden-shape.test.mjs`. Replay needs only a plain static server. The goldens were recorded with the helper and replayed with a plain `http.server`.
- **S1-4 - 14 scenarios, not the minimum 8.** The state tables (wind, last resort, earthquake, New Madrid, no-fault, UM-mandatory, boat law, state disability) are plain data that step B will move into a module, so the scenarios were chosen to hit every state-driven finding at least once (CA, FL, TX, MO, NY, MN, UT, AR, MI, OH, LA, CO, AZ) as well as the screen and answer matrix in the story. The shape test asserts the matrix and that the goldens reach all 16 screens, and that each ends on the summary.
- **S1-5 - The split is a pure move; the strict-mode audit found nothing to fix.** `public/css/app.css` is the inline `<style>` text and `public/js/app.js` is the inline IIFE text, each byte-for-byte (checked by diffing against the original `index.html`: the CSS has no difference, the JS differs only by `o:{}` added to the initial `S` and to the object rebuilt by "Start over", plus a one-line comment above `var S`). Module code is always strict, so the code was audited for sloppy-mode-only constructs: undeclared assignments (a script scanned every assignment target against the declared names), `with`, `arguments.callee`, octal literals, duplicate parameters, strict-reserved or `await` identifiers, `this` at function level, and function declarations inside blocks. None exist, so no code changed for module semantics. The module was also loaded and exercised under jsc's strict module mode with a DOM stub, and the browser goldens run it for real. The IIFE is kept so every helper name stays private exactly as before. The script tag sits at the end of `<body>`; a module script is deferred, so the first `render()` now happens just after parsing instead of during it, which no user can see.
- **S1-6 - D12 checked: accurate on the main points, with two clarifications.** The ES-module split and the "needs http(s), not `file://`" consequence are correct (the Browser pane renders `file://` URLs as static snapshots, so the blank-page failure itself was not reproduced there; the README says "most browsers"). Clarifications, since D12 is append-only: (a) "testable" applies to the new pure modules under `js/overlap/`; `app.js` stays a DOM-bound IIFE covered by the browser goldens, not by jsc unit tests. (b) "CSP-friendly" is true for scripts and style blocks, but four inline `style="..."` attributes remain: `index.html` (progress bar `width:0`), and in `app.js` the US map tile placement, the home-screen icon `transform`, and the "Looks right" row (`border:none;padding:0`). A CSP whose `style-src` lacks `'unsafe-inline'` blocks style attributes, including ones written through `innerHTML` (not `bar.style.width=` or other CSSOM writes). S15 must either allow `style-src-attr 'unsafe-inline'` or turn these into classes, and then check the look in the Browser pane in light and dark (the goldens do not capture style attributes). Left unchanged here because this step must not change behavior.
- **S3a-auto-1 - "Roughly one in eight uninsured drivers" is stale; use the latest dated IRC figure.** The SPEC's auto bullet says roughly one in eight. That matches the Insurance Research Council's 12.6% estimate for 2019 (released March 2021). The latest IRC estimate found is 15.4% for 2023 (released February 2025, "more than one in seven"); no 2024 figure was found as of 2026-10-10. Decision: S8 copy should cite "about 15% of drivers in 2023, per the Insurance Research Council" with the year and publisher, drawn from `research/auto-coverages.mjs` (design input `uninsuredDriverStatistic`). Triple-I's advice page still says "about one in eight" with no year, so it must not be the citation. IRC estimates are restated between editions, so only one edition is ever quoted.
- **S3a-auto-2 - UM/UIM copy never counts or names states.** NAIC and Triple-I pages disagree on how many states require UM/UIM (NAIC 2022: "some states"; NAIC 2023: "most states"; Triple-I: about 20 plus D.C.). Decision: flag copy says the requirement and minimums vary by state and points to the user's own state department of insurance (design input `umUimStateNeutralCopyRule`).
- **S3a-auto-3 - Consumer Reports is used as a corroborating consumer-organization source.** Two collision/comprehensive facts rest on Consumer Reports (10%-of-book-value rule restated, plus a 10-year-old-vehicle mark that no Triple-I page gives). It is a non-commercial consumer organization (authorityType `consumer-org`) but is not named in the SPEC seed list; the S3a authority allowlist must include consumerreports.org or the two facts (`collision-comp-age-trigger`, `collision-comp-drop-loss-caution`) and the shared rule fact's second source must be dropped. The value-to-premium rule also stands on Triple-I alone.
- **S3a-auto-4 - MedPay/health-plan overlap is only partly sourced.** The only authoritative statement found is a drafting note in the NAIC Coordination of Benefits Model Regulation (med pay normally pays first unless state law says otherwise). No authoritative source says MedPay reimburses health-plan deductibles or copays. S10 must phrase the overlap as "ask both insurers" and must not assert that MedPay covers a health deductible.
- **S3a-auto-5 - Limit tiers for UM/UIM, MedPay and towing are a product decision.** No authoritative tier data was found (only an NAIC rental example of $20/day, $600 total, which is an illustration, not a typical value). S5 should use bands plus Not sure and not cite a source for the tiers.
- **S3a-umbrella-1 - The spec's "a shortfall in an underlying limit can void umbrella coverage" is not confirmed by an authoritative source.** `research/umbrella-liability-stack.mjs` supports only that an umbrella attaches after the underlying limit is exhausted and that insurers set minimum underlying limits (Triple-I: about 250,000 auto and 300,000 home for a 1 million umbrella, stated as what "most insurers" want). No NAIC, Triple-I, Consumer Reports or federal page says what happens when an underlying limit is below the requirement or lapses; the sources that do were insurance-education PDFs that could not be fetched, or commercial sites. Decision: S6 words the home-below-minimum Raise item as a request to confirm the umbrella still responds as expected and to raise the underlying limit to the umbrella's stated requirement, and does not assert the consequence as fact until a source is added.
- **S3a-umbrella-2 - UM/UIM on umbrellas is a Question item with no factual claim about defaults.** No authoritative source says whether umbrellas include uninsured/underinsured motorist coverage by default or by endorsement. Only the supported background is used: UM/UIM is an auto-policy coverage that pays the policyholder, and an umbrella is liability protection above underlying limits. S7 asks whether the umbrella extends UM/UIM and whether it can be added, per the spec, without saying "most umbrellas exclude it".
- **S3a-umbrella-3 - Typical underlying figures are context, not rules.** Triple-I's "about $250,000" auto figure is not defined as per-person, combined single limit or split limit, and a 500,000 home requirement is undocumented. The research file includes a derived, clearly labelled preset-versus-requirement table (100/300 below, 250/500 and 500/500 meeting; home 300,000 and up meeting) for S6 to adopt or change in its own DECISIONS entry; it is not a sourced claim.
- **S3a-umbrella-4 - Consumer Reports and an NAIC journal article are used at medium confidence.** Consumer Reports (nonprofit consumer organization) supplies the "cover the assets above your underlying limits" sizing guidance and the 100/300/100 and 250/500/250 recommendations; the NAIC-published Journal of Insurance Regulation article (2020) supplies exclusion wording and the personal-injury coverage point. Neither is in the spec's seed list; the shape tests' allowlist must include consumerreports.org and content.naic.org.
- **S3a-umbrella-5 - Exposure and umbrella-size bands carry no numeric authority.** The sources give only a qualitative rule (cover assets that exceed your underlying liability limits). Bands stay coarse, copy calls them a rough guide, and no net-worth multiple is cited.
- **S3a-home-1 - The water-damage sub-limit flag rests on one state regulator's release, so it is deferred.** `research/home-and-renters.mjs` (fact `water-damage-sublimit-exists`) is supported only by a May 2024 news release from a single state's insurance regulator; no NAIC or Triple-I national statement was found. Citing it would print a state's name in the user-facing source line, against the state-neutral rule (D9, ARCHITECTURE). Decision: the sub-limit flag stays a fast-follow and ships only after the owner decides how to cite it or a national source is found. The $10,000 / $500,000 figures are that release's illustration, not a norm.
- **S3a-home-2 - Homeowners "medical payments to others" does not duplicate the policyholder's own health plan.** Triple-I says it pays injured guests and neighbors and does not pay for your own family or pet (facts `med-pay-what-it-is`, `med-pay-excludes-own-household`). The SPEC's health-overlap bullet asks whether home medical-payments-to-others is still needed when health insurance covers "the same injuries". Decision: S10 should not tell users the home coverage duplicates their health insurance; the honest background is that it covers other people's injuries, and the closer overlap is auto MedPay (see S3a-auto-4). See design input `medPayVersusHealthInsurance`.
- **S3a-home-3 - Home liability tiers above 300,000 are a product decision.** Triple-I supports 100,000 as the usual starting amount and about 300,000 as what most insurers want on the home policy before selling an umbrella (also "some experts" suggest at least 300,000). No authoritative source calls 500,000 or 1,000,000 a typical homeowners tier, so S5 should keep those SPEC presets as buyer-chosen options with "Not sure" and not cite a source for them.
- **S3a-home-4 - Parent-versus-student overlap stays a Question item, with hedged numbers.** Triple-I says a dorm student still in the parents' household is generally covered, typically up to about 10 percent of the contents limit (one undated brochure), while the NAIC adds under age 26 and enrolled, and says only that the parents' policy may pay up to a specified amount. Off campus the parents' policy likely does not apply. Decision: S9 copy says "generally" / "may", never states 10 percent as a rule, and never makes this a Drop; a separate renters policy is raised only as a thing to confirm.
- **S3a-health-1 - No specific federal short-term plan duration is stated as current law.** As of 2026-10-10 the 2024 federal rule (initial term up to 3 months, 4 months total) is still on the books, the three federal departments said on 2025-08-07 they will not prioritize enforcing it, a proposed rule (CMS-9881) has been under White House review since 2026-05-30 with no published text found, and states differ (some ban the plans). Decision: S10 copy says these plans may exclude pre-existing conditions, are not required to cover essential health benefits, and that federal limits on how long they can last have changed and are being revised, then points to the user's state department of insurance. It never prints 3, 4, 12 or 36 months. Facts `stldi-2024-rule-duration-limits`, `stldi-2025-enforcement-pause`, `stldi-federal-status-2026-10-10` in `research/health-supplemental.mjs`.
- **S3a-health-2 - "Supplemental bolt-ons are often redundant" is the spec's claim, not a sourced fact.** No authoritative page was found saying accident, critical illness, cancer or hospital indemnity policies frequently duplicate good primary coverage plus savings. What is sourced: they pay a set cash amount, are not a substitute for comprehensive coverage, and are treated under federal law as excepted benefits. Decision: S10 keeps the spec's Question-to-Drop shape but states only the sourced definition as background and asks whether the narrow payout is worth the premium given the user's main plan and savings.
- **S3a-health-3 - An NAIC-hosted "Supplemental Benefits" overview is not used.** The PDF in NAIC call materials is a September 2021 presentation by an insurance trade association (ACLI), so it is industry advocacy even though it sits on the NAIC site. The supplemental-product facts rest on the CMS fact sheet and the Labor/HHS/Treasury FAQ instead.
- **S3a-health-4 - Open-enrollment framing uses only sourced dates.** HealthCare.gov dates (Marketplace open enrollment 2027: November 1 to January 15, December 15 for a January 1 start) are sourced. No authoritative source gives a typical employer window; HealthCare.gov only says job-based plans may differ and to check with the employer. Decision: health copy may mention the Marketplace dates with the plan year and says "your employer sets its own open enrollment dates"; it does not assert "October to early December" as a fact.
- **S3a-health-5 - The HSA nudge is gated and undated dollar figures are avoided.** HSA eligibility needs a qualifying high-deductible plan, which cannot be inferred from a deductible band. Decision: show the nudge only when the user says they have a high-deductible plan with an HSA, state the three federal tax advantages, and cite the GAO finding that fewer than half of people in high-deductible plans had a linked HSA-type account instead of calling HSAs "commonly underused". HDHP thresholds are year-specific (2026 and 2027 captured in `designInputs.hsaNudge.thresholdsByYear`) and must be dated if shown.
- **S3a-health-6 - Cushion bands line up with the Federal Reserve's table; the $5,000 edge needs an explicit rule.** The spec's bands (under 1,000 / 1,000 to 5,000 / over 5,000) match rows of the Fed's 2025 savings-only table (39% / 23% / 38% of adults). The Fed's top row is "$5,000 or more", so S5 should define the boundary explicitly (suggested: 1,000 to 4,999 and 5,000 or more). The shares are context, not product logic.
- **S3a-other-1 - Card rental coverage is worded "usually secondary", never "primary", unless the card table says so.** NAIC and Triple-I say card rental benefits are usually secondary (they pay after your own auto policy or the rental company's coverage), and the FTC says many cards require declining the rental company's waiver. No consumer-agency or NAIC/III page names a card with primary coverage; that fact can only come from an issuer's guide (S4a, S4b). Decision: S11 flag copy for rental car says "usually secondary" and "ask your card issuer for the terms in writing", and only upgrades the wording for a named card with a verified primary entry. See `research/other-bucket.mjs` facts `rental-card-coverage-usually-secondary`, `rental-card-requires-declining-waiver`.
- **S3a-other-2 - Phone protection plans rest on Consumer Reports only, and its figures are dated.** No NAIC, Triple-I, FTC, CFPB or FCC page on carrier or manufacturer phone-protection plans was found. The facts use a Consumer Reports article updated May 2018 and a card-benefits piece updated September 2022. Decision: S11 uses the structure (fee plus per-claim deductible plus claim cap; card cover generally needs the phone bill paid on that card and usually excludes loss; a homeowners or renters policy may cover a phone, so ask) and never quotes prices, deductibles or caps. The "stop the carrier plan and pay the bill with the card" trim move is the product's inference from two facts, not a sourced recommendation, and is gated on the card table.
- **S3a-other-3 - Credit-card extended-warranty benefits rest on Consumer Reports only.** Neither FTC warranty page mentions card benefits and no CFPB page on this was found. Decision: S11 says "many cards extend the manufacturer's warranty by a year or two; check yours" and asserts a card's benefit only from the verified card table. The neutral value-test wording (adds nothing beyond the included warranty, hidden costs, savings alternative) comes from the FTC.
- **S3a-other-4 - The spec's "life insurance pays no matter what" is hedged.** NAIC pages say term life pays if the insured dies during the term and attach no cause condition; only OPM says "regardless of the cause", and for the federal plan. Decision: AD&D Background copy says life insurance "usually pays whatever the cause of death" while accidental death coverage pays only for accidents, and the AD&D flag stays a Question item. No source supports telling the user to drop AD&D; it supports asking whether total life coverage already covers what the AD&D is for.
- **S3a-other-5 - Consumer Reports, OPM and the FTC are used in the Other bucket.** consumerreports.org (consumer-org) is the only source for the phone-plan, card phone-protection, card warranty-extension and roadside-seller facts; it is not in the SPEC seed list, so the allowlist must include it or those facts (`roadside-sellers-and-card-variation`, `roadside-insurer-addon-claims-check`, `phone-plan-fee-and-deductible`, `phone-card-protection-conditions`, `phone-home-renters-may-cover`, `phone-self-insure-test`, `warranty-card-extension`, `warranty-consumer-reports-advice`) must be dropped. opm.gov (government) supplies the only plain-language statements that AD&D is paid only for accidents and ends with employment; they describe the federal employees' plan (FEGLI), so the facts say so and the copy must not present them as universal.
- **S3a-other-6 - NAIC rental add-on price ranges are not used as copy.** The NAIC Auto Insurance page lists roughly $10-$20 a day for the waiver and smaller amounts for the other rental add-ons, with no date. Decision: S11 may say "roughly, per the NAIC" or omit them. No limit tiers exist for any Other-bucket coverage, so the S5 questions are yes / no / not sure.
- **S3a-other-7 - Motorcycle and boat towing is a question, not a Drop.** The spec says towing on a motorcycle or boat policy often duplicates auto roadside or a card benefit. Sources show only that an auto policy does not cover those vehicles (NAIC) and that Triple-I lists towing after an accident among common and optional boat coverages; Triple-I's motorcycle page does not mention towing. Decision: S11 asks whether the user already has tow help through that policy, a club or a card, and does not assert duplication.
- **S3a-1 - The authority allowlist was applied exactly as the S3a brief gave it, so 14 verified sources were removed.** Allowed hosts (or subdomains): iii.org, naic.org, insureuonline.org, fema.gov, floodsmart.gov, irs.gov, healthcare.gov, cms.gov, hhs.gov, dol.gov, ftc.gov, consumerfinance.gov, federalreserve.gov, insurance-research.org, consumerfed.org, kff.org.
